# خطة الارتقاء بالواجهة وتجربة المستخدم — FONTYPE

**UI/UX Master Plan · Phase 7 · النسخة المقترحة 0.7.0**  
**الحالة:** معتمدة كمرجع تنفيذي · **التاريخ:** 2026-11-24  
**الجمهور المستهدف:** مصمّم خطوط عربي يعمل داخل تطبيق سطح مكتب، وليس مستخدم متصفح.

---

## 0. القرار التنفيذي

الواجهة الحالية وظيفية لكنها ما زالت تُقرأ كواجهة ويب/Framework: بطاقات مستديرة، تدرّجات، توهّج أخضر، شارات ملوّنة، وشريط تنقّل عام لا يشبه برامج التصميم المكتبية. المطلوب ليس "تجميل ألوان"، بل **إعادة تعريف التطبيق كأداة احترافية**: نافذة أدوات، لوحات راسية (docks)، مساحة رسم مركزية، مفتش خصائص، شريط أدوات صغير، حواف hairline، كثافة عالية، وتركيز بصري على الرمادي المحايد مع لون واحد هادئ للاختيار فقط.

الهدف النهائي: عندما يفتح المصمّم FONTYPE يجب أن يشعر أنه داخل أداة تصميم مثل Adobe Illustrator / Photoshop / After Effects، لا داخل dashboard ويب.

هذه الخطة تحكم المرحلة 7 بالكامل. لا تُعدّل منطق المحرك، عقود Rust، أو منطق التشكيل أثناء تنفيذها.

## 1. التشخيص الحالي

| # | الملاحظة | الأثر على الإحساس | القرار التصحيحي |
|---|---|---|---|
| 1 | الأخضر `#4fd1b0` مستخدم في الشعار، الحالات النشطة، التركيز، الشارات، خطوط القياس، المراسي، وأزرار primary | اللون يهيمن على العين ويجعل الواجهة تبدو كمنتج SaaS لا أداة تصميم | استبداله بلون أزرق/رمادي فولاذي هادئ، وتضييق استخدامه إلى selection/focus فقط |

| 6 | عناوين مختلطة بين `PanelHeader` و `h2`/`h3` | تسلسل هرمي غير متسق | نظام heading واحد لكل لوحة: title + meta + actions |
| 7 | حالات الواجهة غير مكتملة: لا توجد حالة فارغة موجهة، لا توجد حالة تحميل موحّدة، لا توجد رسائل خطأ قابلة للتصرف | المستخدم لا يعرف ماذا يفعل بعد الفشل | نمط حالة موحّد: فارغ / تحميل / خطأ / نجاح مع إجراء تالٍ واضح |
| 8 | الوصولية تعتمد على اللون في أماكن متعددة | تعارض مع WCAG | كل حالة تحتاج أيقونة + نص، وليس اللون وحده |
| 9 | معظم العمليات القابلة للسحب بلا بديل رقمي كامل في كل السياقات | حاجز للوحة المفاتيح وقارئ الشاشة | قاعدة: كل قيمة قابلة للسحب تحتوي حقل رقمياً وخطوة كيبورد واضحة |
| 10 | لا يوجد focus trap موثّق في الحوارات، ولا roving tabindex للقوائم | تنقّل غير متوقع | نمط حوار/قائمة موحّد مع إدارة تركيز صريحة |

> ملاحظة لغوية: مصطلح "Framework look" هنا يعني مظهر القوالب الجاهزة: بطاقات، تدرّجات، توهّج، pills، وأيقونات زينة. كلها تُزال من اللغة البصرية المستهدفة.

## 2. المبادئ الحاكمة

1. **الأداة قبل الزينة:** كل بكسل يخدم مهمة المصمّم أو يوضّح حالة النظام.
2. **الرمادي هو الهوية:** 80–90% من الواجهة رمادي محايد؛ اللون استثناء وظيفي.
3. **لا لون بدون سبب:** الأخضر يبقى فقط لحالة `ready`، الأحمر للفشل، الأصفر للمراجعة، الأزرق للاختيار/التركيز.
4. **الكثافة ليست فوضى:** مسافات صغيرة، مع تسلسل هرمي واضح وفواصل دقيقة.
5. **RTL أصيل:** الخصائص المنطقية `inset-inline-*`، `margin-inline-*`, `padding-inline-*`؛ لا عكس يدوي للواجهة.
6. **المساحة المركزية مقدّسة:** اللوحة الوسطى هي العمل؛ اللوحات الجانبية قابلة للطي ولا تزاحمها.
7. **كل إجراء قابل للوصول بالكيبورد:** لا استثناء للسحب أو الرموز أو القوائم.
8. **الحالة تُقال بالكلمات:** لا تعتمد على اللون أو الأيقونة وحدها.
9. **الاستعادة دائماً متاحة:** undo/redo، حفظ تلقائي، نسخ احتياطي، ورسالة "تم الحفظ" غير مزعجة.
10. **المصطلح التقني في مكانه:** العربية في الواجهة، والمصطلح الإنجليزي في tooltip أو "متقدم".

**قاعدة اللون:** إذا لاحظ المستخدم "اللون" قبل "الشكل والمسافة"، فالواجهة فاشلة.

### 3.2 ما يُلغى نهائياً

- التدرّجات radial/linear على الخلفيات.
- `box-shadow` على البطاقات العادية؛ يبقى فقط للحوارات/qmenu/palette.
- `backdrop-filter` و glassmorphism.
- التوهّج `accent-glow`.
- الأزرار الأساسية الخضراء العريضة.
- الشارات الدائرية لكل شيء؛ تُستبدل بنص حالة صغير + أيقونة.
- الأنصاف الكبيرة، الحواف الملونة السميكة، الـ pills الزينة.

### 3.3 ما يُعتمد

- أسطح صلبة، حواف 1px، أنصاف 2–4px.
- خط UI: `IBM Plex Sans Arabic`، أحجام 11/12/13px.
- أرقام القياس: mono مع tabular numerals.
- عناوين لوحات: 12px بوزن 600، تسميات: 10px دون تحويل حالة للأحرف العربية.
- فاصل رأسي 1px بين الدوكس، فاصل أفقي 1px أسفل رؤوس اللوحات.

## 5. نظام المكوّنات

كل مكوّن في `src/ui/` يجب أن يمتلك: HTML دلالي، حالات `hover/focus/active/disabled/loading/error`، اسم وصولي، ومواصفة اختبار.

| المكوّن | المواصفة | الحالات | الوصولية |
|---|---|---|---|
| `MenuBar` | قوائم `file/edit/view/project/help` باختصارات | open/closed | `role="menubar"`، `aria-haspopup`، سهم تنقّل |
| `Toolbar` | مجموعة أدوات مدمجة بفواصل 1px | active/disabled | `role="toolbar"`، `aria-pressed` |
| `ToolRail` | أدوات الرسم داخل canvas | select/hand/grid/anchor | أسماء عربية + tooltip بالاختصار |
| `Dock` | لوحة قابلة للطي/السحب | collapsed/expanded/resizing | زر طي صريح، حفظ العرض |
| `InspectorSection` | عنوان + محتوى + إجراء | open/closed | `aria-expanded`، ترتيب منطقي |
| `NumericField` | قيمة رقمية + وحدة + step + lock | normal/locked/invalid | `aria-label`، `aria-describedby` للوحدة |
| `SegmentedControl` | 2–4 خيارات متجاورة | selected/disabled | `radiogroup` أو tablist حسب السياق |
| `TreeList` | مجموعات → حروف → أشكال | selected/expanded/empty | `role="tree"`، keyboard arrows |
| `StatusBadge` | نص + أيقونة + لون | ready/review/error/imported | لا لون فقط |
| `CommandPalette` | بحث، مجموعات، تنفيذ | open/filter/empty | focus trap، `aria-activedescendant`، Escape |
| `Dialog` | حوار modal مع خلفية | open/closing | focus trap + return focus + `aria-modal` |
| `Toast` | إشعار قابل للتصرف | ok/error/info | `aria-live="polite"`، لا يحجب التركيز |
| `CanvasStatus` | إحداثيات، zoom، snap، حفظ | live/idle | `role="status"`، تحديث محدود |

### 5.1 قواعد بناء المكوّن

- لا يُنشأ مكوّن جديد قبل تعديل المكوّن القريب منه في `src/ui/components.tsx`.
- لا `div` قابل للنقر؛ استخدم `button` أو `role`/keyhandler كامل.
- كل أيقونة داخل `Icon` لها `aria-hidden=true`؛ الاسم يأتي من النص أو `aria-label`.
- كل حالة لونية تقترن بنص أو أيقونة.
- لا `title` كبديل عن tooltip/وصف وصولي.

## 6. ترتيب اللوحات والمعلومات

### 6.1 اللوحة اليسرى — Glyphs Dock

الغرض: الوصول إلى كل خانة دون مغادرة السياق.

الترتيب:

1. حقل بحث صغير.
2. فلتر المجموعة + الحالة في سطر واحد.
3. شجرة: `المجموعة → الحرف → الأشكال الأربعة`.
4. حالة مختصرة لكل خانة: أيقونة + كلمة.
5. إجراءات: استيراد، فتح في المحرر، تحديد كمصدر مرجعي.

### 6.2 المساحة المركزية — Glyph Workspace

الغرض: وضع الرسم داخل نظام القياس.

الترتيب:

1. Tool rail رأسي ضيق.
2. شريط خيارات الأداة أعلى اللوحة فقط عند الحاجة.
3. rulers أعلى ويسار.
4. canvas مع Em frame، metric lines، guides، anchors.
5. شريط حالة اللوحة: إحداثيات، zoom، snap، upm.
6. لا توجد بطاقات عائمة فوق الرسم إلا أدوات zoom صغيرة جداً.

### 6.3 اللوحة اليمنى — Inspector Dock

الغرض: كل ما يغيّر الخانة الحالية، بترتيب يتبع تفكير المصمّم.

| الترتيب | القسم | المحتوى |
|---|---|---|
| 1 | Import | المصدر، الوضع، معاينة صغيرة، استبدال مع revision |
| 2 | Transform | X، Y، Scale، lock، reset |
| 3 | Metrics | Advance، LSB، RSB، baseline offset |
| 4 | Anchors | القوائم، الإحداثيات، الاقتران، مراجعة التغيير |
| 5 | Validation | findings مع إجراء "اذهب للخانة" |
| 6 | History | آخر التغييرات + undo/redo |

### 6.4 مساحة البناء — Build Workspace

تصبح لوحة/دوكس بدلاً من تبويب ويب عريض:

- يسار: إعدادات التشكيل + إجراءات البناء.
- يمين: معاينة نص حقيقي + جدول corpus + سجل البناء.
- أعلى: حالة المحرك + آخر بناء + ملفات ناتجة.
- أسفل: فحص الجداول بنص + أيقونة، لا بطاقات كثيرة.

## 7. تدفقات تجربة المستخدم

### 7.1 التشغيل الأول

1. ترحيب مختصر في حوار غير قابل للتخطي فقط عند غياب مشروع.
2. اختيار: مشروع جديد / فتح مشروع / فتح مثال جاهز.
3. إنشاء المشروع يولّد المخزون فوراً.
4. يفتح Dock الحروف مع أول خانة مطلوبة محددة.
5. رسالة واحدة: "اختر خانة ثم استورد SVG".

### 7.2 استيراد حرف

1. اختيار الخانة من الشجرة.
2. استيراد SVG أو إفلاته.
3. معاينة + تحذيرات قبل الحفظ.
4. اختيار وضع الملاءمة.
5. حفظ في الخانة.
6. فتح المحرر تلقائياً مع إبراز baseline.

القاعدة: اسم الملف لا يغيّر هوية الخانة.

### 7.3 ضبط الحرف

1. تحريك/تحجيم بالأدوات أو إدخال أرقام.
2. snap شفاف مع عرض الهدف عند التفعيل.
3. تعديل المراسي عبر قيم أو سحب.
4. ظهور تنبيه مراجعة إذا تغيّرت هندسة الرسم.
5. حفظ الحالة وتمكين زر الاعتماد فقط بعد نجاح الفحص.

### 7.4 البناء والتشكيل

1. فحص المحرك.

2. مراجعة إعدادات التشكيل.

3. بناء OTF/TTF.

4. قراءة الفحوص كقائمة نصوص لا كبطاقات ملوّنة.

5. معاينة نص عربي حقيقي من HarfBuzz.

6. فتح corpus؛ أي فشل يفتح الخانة المرتبطة مباشرة.

### 7.5 الاستعادة

- كل استيراد بديل ينشئ revision محفوظاً.
- زر "استعادة" يظهر في Inspector مع تاريخ الإصدار.
- نسخة احتياطية كاملة للمشروع قابلة للاستعادة من شريط الأدوات.

## 8. الوصولية الكاملة — WCAG 2.2 AA

### 8.1 المعايير غير القابلة للتفاوض

| المعيار | المتطلب |
|---|---|
| تباين النص | ≥ 4.5:1 |
| تباين حدود الأدوات | ≥ 3:1 |
| التركيز | ring أزرق 2px واضح على كل عنصر قابل للتفاعل |
| الاسم الوصولي | كل زر/حقل/أيقونة له `aria-label` أو نص مقروء |
| اللون | لا يُستخدم وحده للدلالة |
| الحركة | `prefers-reduced-motion` يوقف انتقالات الدخول |
| التكبير | 100–200% دون فقدان وظائف أو overflow |
| RTL | ترتيب التركيز يتبع الترتيب البصري العربي |
| الحوارات | focus trap + Escape + إعادة التركيز لعنصر الاستدعاء |
| القوائم | `menubar/menuitem` + تنقّل أسهم |
| الرسم | بديل نصي لكل أداة وكل حالة تحرير |

- [ ] قارئ شاشة يقرأ اسم الخانة، الحالة، القيمة الرقمية، والوحدة.
- [ ] التركيز لا يهرب من الحوار.
- [ ] لا يوجد عنصر focus مستتر خلف لوحة.
- [ ] تقليل الحركة مفعّل فعلياً.
- [ ] 150% zoom على 1280×800 بلا فقدان.
- [ ] كل tooltip له بديل نصي في `aria-describedby`.

## 9. قابلية الاستخدام

### 9.1 قواعد سلوكية

- التأكيد الفوري على كل فعل صغير: "تم الحفظ"، "تم الاستيراد"، لكن بدون إشعار متكرر مزعج.
- الأخطاء تقول **ماذا حدث + لماذا + ماذا أفعل بعدها**.
- لا تعطّل زراً دون سبب مرئي؛ اعرض `title`/نص مساعدة عند disabled.
- القيم الرقمية تُحفظ مع وحدتها FU.
- كل تغيير هندسي يضيف علامة "تحتاج مراجعة" ولا يُخفيها.
- الفشل في المحرك لا يغلق التطبيق؛ يعرض سجل المحرك مع مسار التقرير.

### 9.2 حالات فارغة إنسانية

| الحالة | العنوان | الجملة | الإجراء |
|---|---|---|---|
| لا مشروع | "لا يوجد مستند مفتوح" | "أنشئ مشروعاً لتبدأ المخزون." | مشروع جديد |
| مخزون فارغ | "لا توجد خانات" | "حدّث المخزون من إعدادات المشروع." | تحديث |
| خانة بلا SVG | "هذه الخانة تنتظر رسماً" | "اسحب SVG هنا أو اختر ملفاً." | استيراد |
| لا بناء | "لم يُنشأ خط بعد" | "ابنِ الخط لعرض معاينة HarfBuzz." | بناء |
| فشل corpus | "هناك حالات فشل" | "افتح الخانة المرتبطة بالأول فشل." | إصلاح |

### 9.3 Micro-interactions

- 120–160ms فقط، ease-out، بلا مرونة مبالغ فيها.
- hover يغيّر خلفية 2–4% ولا يغيّر الحجم.
- active يغيّر الحد أو خلفية بسيطة.
- لا تحريك للبطاقات، لا pop، لا bounce.

## 11. خطة الاختبار والجودة

### 11.1 مصفوفة فحص

| البعد | الأداة | الشرط |
|---|---|---|
| وحدة | Vitest | كل مكوّن جديد له test |
| TypeScript | `npm run build` | صفر أخطاء |
| Python engine | `uv run --project engine pytest -q` | كما هو، بدون تعديل |
| Rust | `cargo test --manifest-path src-tauri\Cargo.toml` | كما هو، بدون تعديل |
| وصولية | axe-core عبر Playwright | 0 serious/critical violations |
| بصري | Playwright screenshots | مقارنة يدوية على 1280/1440/1920 |
| كيبورد | Playwright script | إكمال 5 تدفقات دون فأرة |
| RTL | DOM + computed style | `dir=rtl`, `lang=ar`, logical properties |
| Console | browser console | 0 errors |
| Tauri | `cmd /c dev.bat` | إقلاع Vite + fontype.exe |

### 11.2 معايير القبول البصرية

- لا يظهر أي تدرّج أو توهّج في الواجهة.
- اللون الأزرق لا يظهر إلا في focus/selection/active tab.
- الأخضر لا يظهر إلا في حالة `ready` بحجم صغير.
- لا توجد بطاقة ذات shadow داخل لوحة عادية.
- كل الفواصل 1px، لا حدود ملوّنة سميكة.
- المسافة بين المجموعات 8px، بين الأقسام 12px، بين اللوحات 1px.
- لا overflow أفقي أو رأسي على 1280×800 فأعلى.

### 11.3 معايير القبول الوصولية

- كل عنصر تفاعلي يصل إليه `Tab` وله focus مرئي.
- لا `role` وهمي على عنصر غير تفاعلي.
- كل حوار يغلق بـ Escape ويعيد التركيز.
- كل حالة خطأ/مراجعة لها نص.
- كل قيمة قابلة للسحب لها حقل رقمي.
- قارئ الشاشة يقرأ الترتيب بالعربية بشكل صحيح.

## 13. القيود والثوابت
