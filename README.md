# FONTYPE — استوديو الخطوط العربية

تطبيق سطح مكتب لتحويل رسومات SVG مرسومة في Illustrator إلى خط عربي قابل للتثبيت.
الخطة الكاملة في [`PLAN/`](PLAN/README.md).

## الحالة الحالية

**المراحل 0–5 مكتملة** · **المرحلة 6 — التثبيت والإصدار: MVP جاهز** (الإصدار `0.6.0`).

المسار الذي تم إثباته فعلياً:

```text
SVG واحد → هندسة مُوحّدة بإحداثيات الخط → UFO → OTF + TTF → فحص الجداول → HarfBuzz → مجموعة اختبار التشكيل
```

الاختبارات الحالية: Python 26 · Rust 12 · الواجهة 26 — كلها ناجحة.

## التشغيل

المتطلبات: Node 24، Rust (MSVC على Windows)، `uv`، WebView2.

```powershell
# تثبيت التبعيات (مرة واحدة)
npm install
uv sync --project engine --all-extras

# تشغيل التطبيق في وضع التطوير
npm run tauri dev

# الاختبارات
npm test
uv run --project engine pytest -q
cargo test --manifest-path src-tauri/Cargo.toml
```

أو من مستكشف Windows: انقر مرتين على `dev.bat` في جذر المشروع. الملف يتحقق من `npm` و`uv`،
يثبّت التبعيات عند غيابها، ثم يقلع `npm run tauri dev`. أغلق النافذة أو اضغط `Ctrl+C` لإيقاف التطبيق.

لإعادة توليد أيقونة التطبيق:

```powershell
engine\.venv\Scripts\python.exe scripts\make_icon.py
npx tauri icon assets\icon.png
```

## واجهة التطبيق

- الهيكل عربي RTL بالكامل، مع خط **IBM Plex Sans Arabic** محلي الحزم (لا يُحمّل من الإنترنت).
- الأيقونات من **Phosphor** مُجمّعة محلياً عبر نقاط استيراد مباشرة لتقليل حجم الحزمة.
- شريط علوي مضغوط وتبويبات بأيقونات، ولوحة مشروع قابلة للإخفاء، وشريط حالة سفلي وإشعارات منبثقة.
- مساحة العمل تتكوّن من شريط أدوات رأسي، وشريط عرض عائم، وشريط حالة حيّ، ومفتش أقسام قابل للطي.
- الاختصارات: `V` تحديد، `H` تحريك، `Space` تحريك مؤقت، `+`/`−` تكبير، `0` احتواء الرسم، `Ctrl+Z`/`Ctrl+Shift+Z` تراجع/إعادة، و`?` نافذة الاختصارات.

## قرارات مُثبّتة في المرحلة 0

- المحرك عملية Python 3.12 محلية (لا رفع أي بيانات للإنترنت) تتواصل عبر JSON-lines.
- الواجهة عربية أولاً مع معاينة نص RTL صحيحة؛ مصطلحات OpenType تُعرض في التلميحات.
- هوية الحرف تأتي من خانة المشروع لا من اسم ملف SVG.
- مخطط المشروع `0.1.0` وقابل للترقية؛ الحفظ ذري (atomic).

## المرحلة 1 باختصار

- يُنشأ المخزون تلقائياً عند إنشاء المشروع: 57 حرفاً وعلامة ورقماً مع أشكال الوصل المطلوبة (140 خانة).
- لكل خانة معرّف ثابت (`beh.initial` → `beh.init`) لا يتأثر باسم ملف SVG.
- فحص الاستيراد يوفّر معاينة فورية في وحدات الخط، تحذيرات منظّمة، وأربع طرق تحجيم.
- الاستبدال يحتفظ بالنسخة السابقة في `glyphs/<base>/<form>.rev-*.svg` مع البصمة والوقت.
- السحب والإفلات فوق الخانة أو منطقة المعاينة مدعوم عبر أحداث Tauri الأصلية.

## المرحلة 2 باختصار

- مساحة عمل قابلة للتكبير حول المؤشر والتحريك بالسحب، مع احتواء الـ Em أو الرسم المستورد.
- مخطط الحرف يُرسم مباشرة من `previewPath` المُخزّن في المشروع، مع حدود هندسية دقيقة.
- مساطر أفقية وعمودية بوحدات الخط تتكيّف مع التكبير، وخطوط قياس قابلة للسحب والقفل والإخفاء.
- أدلة مخصصة تُنشأ من المسطرة أو رقمياً، وتُحفظ في المشروع مع نطاقها وحالتها.
- شبكة كبرى/صغرى، وسجل أهداف التقاط يشمل خطوط القياس والأدلة وحدود الرسم والتقدّم والشبكة.
- الالتقاط بحساسية بكسلية مع هستيريسيس وأولوية حتمية، وخطوط إرشاد ذكية؛ `Alt` يعطّله مؤقتاً و`Shift` يقيد المحور.
- حقول رقمية X/Y والمقياس وعرض التقدّم والحواف الجانبية، مع تراجع/إعادة كاملة لتعديلات مساحة العمل.

## المرحلة 3 باختصار

- أسماء Glyph الداخلية مشتقة من الخانة (`beh.initial` → `beh.init`) مع ربط Unicode بالشكل المفرد فقط.
- أمر المحرك `build_source` يكتب `source/fontype.ufo` يحوي المخططات، الأعرض، المراسي، الأصناف والمجموعات وبيانات المشروع.
- المراسي مقترحة تلقائياً حسب دور الخانة: `top`/`bottom`، `entry`/`exit` للحروف الواصلة، و`*-mark` للعلامات.
- محرر مرئي في مساحة العمل: سحب المقابض، إحداثيات رقمية، قفل/حذف، رموز توافق وخطوط وصل، وحالات مراجعة.
- استبدال SVG يحتفظ بالمراسي والقياسات ويعلّم المراسي المرتبطة بالهندسة للمراجعة عند تغيّر الحدود مادياً.

## المرحلة 4 باختصار

- مولّد ميزات OpenType ينشئ `init` و`medi` و`fina` بسياق وصل صحيح، و`ccmp` اختياري للام ألف.
- `ufo2ft` يولّد GPOS وGDEF من المراسي المُوحّدة مع `public.openTypeCategories`.
- البناء ينتج OTF وTTF عبر fontmake، ويفحص الجداول والـ cmap والأشكال، ويحفظ تقريراً وسجل مترجم داخل `reports/<buildId>/`.
- حالة كل بناء تُسجّل في `project.json` مع البصمة ومسارات الملفات.

## المرحلة 5 باختصار

- معاينة HarfBuzz محلية بثلاثة أوضاع: حرفاً بحرف، كلمة بكلمة، فقرة كاملة.
- مجموعة الاختبار `arabic-core-preview-v2` تضم 11 حالة: الأشكال الأربعة، انتقالات الوصل يميناً ويساراً، الحركات المفردة والمتراكبة، لام ألف الاختيارية، الترقيم، والنص المختلط.
- التوقعات والنتائج بترتيب بصري RTL (الحرف الأيمن أولاً)، وهو ما يوضّحه وصف الواجهة.
- فشل أي حالة يعرض المتوقع مقابل الناتج، ويمكن الانتقال من شريحة الحرف إلى خانتها الأصلية بنقرة واحدة.
- مثال مُثبت: مشروع اصطناعي كامل بـ 141 حرفاً يجتاز 11/11 حالة دون ملاحظات.

## المرحلة 6 باختصار

- محرر بيانات التصدير: الإصدار، المصمم، حقوق النشر، الترخيص — تُكتب إلى UFO/name table.
- نسخ احتياطي بوقت محدد داخل `<project>/backups/` واستعادة منه من لوحة البناء.
- إلغاء مهام المحرك، شريط تقدّم، وسجل مترجم قابل للمراجعة.
- الأقفال `engine/uv.lock` و`package-lock.json` و`src-tauri/Cargo.lock` تثبّت أدوات البناء.

## مجموعة الأحرف المدعومة

المجموعة المُثبّتة `arabic-core` (Unicode 16.0.0) تغطي 57 حرفاً/علامة و140 خانة شكل:

| المجموعة | العدد | المدى |
|---|---:|---|
| حروف عربية | 29 | U+0627–U+064A |
| همزات وألفات ممدودة | 6 | U+0621–U+0626 |
| تطويل | 1 | U+0640 |
| حركات | 8 | U+064B–U+0652 |
| ترقيم عربي | 3 | U+060C، U+061B، U+061F |
| أرقام عربية | 10 | U+0660–U+0669 |

النص اللاتيني والمسافة يُعاملان كرموز غير مُخطّطة في المعاينة (يظهران كـ `.notdef`/`space`)؛ هذا متوقع لأن المجموعة عربية فقط. وصلات لام ألف اختيارية وتحتاج رسوم `lam_alef.*` مستوردة؛ إذا غابت يُصدر المحرك تحذيراً واضحاً.

## دليل البدء السريع

1. أنشئ مشروعاً واختر اسم العائلة وUPM (1000 أو 2048).
2. افتح «مخزون الخانات» واستورد SVG لكل شكل مطلوب؛ هوية الخانة لا تتأثر باسم الملف.
3. في «مساحة العمل» اضبط العرض والحواف، ثم راجع المراسي المقترحة وحالات المراجعة.
4. في «المشروع» املأ بيانات التصدير (الإصدار، المصمم، الترخيص) واحفظها.
5. في «البناء والمعاينة» فعّل خيارات التشكيل واضغط «بناء OTF + TTF».
6. اكتب نصاً عربياً في المعاينة وشغّل «اختبار المجموعة»؛ تابع أي فشل إلى خانته.
7. استخدم «نسخة احتياطية» قبل أي تغيير كبير، و«استعادة نسخة» عند الحاجة.

## القيود المعروفة

- لم يُنتج مُثبّت Windows بعد؛ تم تشغيل `fontype.exe` الناتج عن البناء التصحيحي بنجاح.
- مصفوفة الدقة العالية (DPI/multiple scales) لم تُختبر يدوياً بعد.
- لا يوجد مشروع نموذجي مُرفق؛ دليل البدء أعلاه يوفّر المسار الكامل.
- فحوص البناء بنيوية وظيفية؛ لا تحكم على الجمال البصري أو جودة الاقتران بين الأشكال.
- التحويل إلى TTF يمر عبر cubic→quadratic؛ inverse curvature قد يحتاج مراجعة بصرية للرسومات الحادة.
- المحرك لا يقرأ شبكة الإنترنت إطلاقاً؛ كل المعالجة محلية.
